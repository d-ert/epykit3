# epykit 1.0-prep Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Land the library-side changes for epykit 1.0 — doc fixes, deprecation-shim cleanup, three targeted breaking-change fixes, a public-surface audit, and the release mechanics — on a `1.0-prep` branch off `p0-fixes`, merge to `main`, and tag `v1.0.0`.

**Architecture:** Single feature branch off `p0-fixes`. Each task lands as one focused commit so review is easy and bisect is precise. Behavior-changing tasks land first (with deprecation shims to keep 0.7.6 callers working), docs follow once new behavior is in place, release mechanics close out. The companion `paper` branch (for benchmark + paper finish) runs in parallel and is covered in a separate plan.

**Tech Stack:** Python 3.9-3.12, `uv` for env management, `pytest` (with `slow` marker), `ruff` (F-only baseline), `mypy`. Polars + numpy + scipy + statsmodels for the library itself.

_DEMOTED_TO_DMC = {

def __getattr__(name: str):
    """Module-level __getattr__ provides backward compat for names removed
    from `__all__` at 1.0.

    Returns the function from the appropriate submodule and emits
    DeprecationWarning pointing users at the new import path. Shim is
    scheduled for removal in 1.2.
    """
    if name in _DEMOTED_TO_DMC:
        import warnings
        from . import dmc as _dmc_mod
        warnings.warn(
            f"epykit.{name} is no longer a top-level export; use "
            f"`from epykit.dmc import {name}` instead, or use the "
            f"recommended `epykit.tl.dmc` wrapper. This shim will be "
            f"removed in epykit 1.2.",

## Notes for the implementer

1. **Order matters.** Tasks 1-7 land low-risk changes first; Task 8 is the behavior change; Tasks 9-10 update docs to match the new behavior; Tasks 11-12 are hygiene; Tasks 13-15 are release mechanics. Reordering risks landing docs that describe behavior that hasn't shipped yet.

2. **Each task is one commit.** Don't squash within a task and don't combine tasks. Bisect needs to be able to land on individual changes.

3. **Deprecation shims are load-bearing.** Tasks 4, 5, 6 all add shims so 0.7.6 callers keep working. Resist the urge to skip the shim "for cleanliness" — the shims live one minor cycle and remove cleanly in 1.2/2.0 with no surprise to users.

4. **The CHANGELOG entry in Task 13 is the user-facing summary of everything in this plan.** If a task lands a behavior change that is not in the changelog template, add it before merging.

5. **The companion paper-track branch (`paper`) runs in parallel** and may merge before or after this branch. Conflict surface should be zero (this plan touches only `src/epykit/**`, library docs, version files, and `docs/superpowers/`; paper branch touches `benchmark/**` and `paper/**`). If a conflict arises in `CHANGELOG.md`, resolve by merging both sets of entries under their respective sections.

6. **If the public-surface audit (Task 7) surfaces a bigger issue** (something that needs more than a docstring or kwarg rename), log it in `2026-06-01-public-surface-audit.md` under "1.1 backlog" and continue — the 1.1 polish release is the right place for additional surface changes.
