## 1. Decisions taken during brainstorming

Recorded so the next session doesn't re-litigate them:

1. **`lr+` defaults stay OFF at 1.0.** No bare-engine behavior change vs. 0.7.6 when users do nothing. Library docs are rewritten to describe `lr+` as a *tunable power stack*, not as "recommended defaults." Paper Methods reports `lr` and `lr+` numbers side-by-side, transparent about the choice.
2. **1.0 = stamp current surface + targeted cleanup + three breaking-change fixes** (per the Option B brainstorm in §2.5). No new features. Scope is doc fixes, deprecation-shim cleanup, type-narrowing on a few enums, a public-surface audit pass, plus three targeted breaking changes that are cheaper now than after 1.0.
3. **`DMCStore` stays public.** Users get it back from `tl.dmc(..., return_store=True)`; hiding it would be confusing.
4. **Library 1.0 and paper run as two independent branches** off `p0-fixes`. They touch disjoint files (`src/epykit/**` + library docs vs. `benchmark/paper/**` + benchmark scripts). Either can merge to `main` first; 1.0 tag waits until both land.
5. **Take three targeted breaking-change fixes at 1.0** while pre-1.0 status permits it: fix `power_stack="auto"` to engage the full lr+ stack, demote five low-level DMC functions from `__all__`, and rename `pp.unite()` to signal that it's a state-marker rather than a computation. All three ship with deprecation shims so 0.7.6 → 1.0 is not a hard break.

## 2. Library 1.0 track

### 2.1 Doc-only fixes (no behavior change)

- **Rewrite the `lr+` sections in `README.md` and `CLAUDE.md`** to describe it as a tunable stack of four opt-in knobs, not as "recommended." Specifically: drop language that implies users should turn it on for production work, replace with neutral "if you want to close the gap to methylKit/DSS, the `lr+` stack of `neighbour_combine=True`, `fdr_method="fdr_tsbh"`, `sep_fallback=True`, `dispersion="eb"` does that — see benchmark §X." Keep the benchmark numbers in `benchmark/REPORT.md` exactly as written.
- **Add `dispersion="eb"` to `dmc.process_chromosomes_dmc` public docstring.** Currently the docstring lists `"site" | "chrom" | "shrink"` but `tl.dmc` defaults to `"eb"`. (audit finding #4)
- **Fix `pp.unite()` docstring** to make explicit that this is a lazy state-marker, not a materialization — `md.store` does NOT change. (audit finding #7)
- **Update `CLAUDE.md`'s "Pre-1.0 (currently 0.7.2)" line** to "1.0 (stable API)" after the version bump.

### 2.2 Public surface (Bucket B revised)

After verification: `asm`, `hmr`, `pmd`, `dvc`/`dvr`, `clocks`, `impute` all have test files. They're not abandoned — they're stable enough for the top-level namespace. **No `epykit.experimental.*` namespace introduced at 1.0.**

What does change:
- **Audit the 54 top-level exports** and confirm each one is reachable through documented examples in `docs/` or `README.md`. Anything that has tests but no user-facing docs gets either (a) a short docs/reference entry or (b) demoted to a submodule import path (`from epykit.clocks import age_clock` instead of `epykit.age_clock`). Goal: every top-level export is one a user could plausibly find from the docs.
- **`MethylData._analysis_root`**: rename to `analysis_root` (no underscore) and document it as a stable read-only attribute. The pp.* functions that set it are the contract.
- **`apply_multiple_testing_correction`'s `DMCStore | DataFrame` overload**: keep as-is for 1.0, but add a clear note in the docstring naming both code paths. Splitting into two functions is a 2.0 question. (audit finding #10)

### 2.3 Cleanups

- **Remove the `method="hmm"` deprecation shim** in `tl.dmr` (currently emits FutureWarning, scheduled for 0.8 removal). 1.0 either removes it or commits to it — removing is cleaner. (audit finding #9)
- **Type-narrow string-enum params**: `to_bedgraph`/`to_bigwig` `value` kwarg → `Literal["beta", "coverage", "N_meth"]` with runtime validation that raises on unknown values. (audit finding #11)
- **`power_stack: str | bool`** in `tl.dmc`: narrow to `Literal["auto", "off"] | bool`, document the truthiness behavior, reject other strings. (audit finding #5)

### 2.4 Targeted breaking-change fixes (Option B from API brainstorm)

Three changes that are cheaper to make at 1.0 than later. Each ships with a deprecation shim so existing 0.7.6 code continues to run (with warnings) and the actual removal happens in 2.0.

#### 2.4.1 Fix `power_stack="auto"` to engage the full lr+ stack

Currently at [src/epykit/tl.py:477-496](src/epykit/tl.py:477), `power_stack="auto"` only flips `neighbour_combine` and `sep_fallback`, and only when `min_n ≤ 2`. It does NOT flip `fdr_method` to `"fdr_tsbh"`, and it does NOT engage above n=2. This contradicts the README/CLAUDE.md narrative that lr+ is a four-knob stack closing the gap to methylKit/DSS.

Change at 1.0:
- `power_stack="auto"` and the new alias `power_stack="lr+"` flip `neighbour_combine=True`, `fdr_method="fdr_tsbh"`, `sep_fallback=True`. `dispersion` already defaults to `"eb"` so no change there.
- The stack engages at any n, not just n≤2. The n≤2 conservative carve-out (which auto-engaged in old behavior) becomes `power_stack="conservative"`.
- Emit an `INFO` log line per knob auto-flipped so users see what they got.
- `power_stack=True` continues to work as an alias for `power_stack="lr+"`.
- `power_stack=False` and the default (unset) leave all four knobs at their explicit user-passed values.
- Add a `Literal["auto", "lr+", "conservative", "off"] | bool` type annotation; reject other strings.

This is a behavior change for any user who set `power_stack="auto"` on a dataset with `min_n > 2`. CHANGELOG entry must call this out prominently.

#### 2.4.2 Demote five advanced DMC functions from top-level `__all__`

Currently at [src/epykit/__init__.py:107-113](src/epykit/__init__.py:107), the following are top-level exports with a source-code comment "advanced users; tl.dmc is the recommended entry":

- `process_chromosomes_dmc`
- `apply_multiple_testing_correction`
- `empirical_fdr_for_dmc`
- `fisher_exact_vectorized`
- `shrink_meth_diff`

The source-code comment is not visible to users in IDE autocomplete; both paths show up as equally-promoted entries. Two paths to the same destination is the rough edge.

Change at 1.0:
- Remove these five names from `__all__` in `src/epykit/__init__.py`.
- Functions remain importable as `from epykit.dmc import process_chromosomes_dmc` (no code deletion).
- Add a `__getattr__` shim in `src/epykit/__init__.py` that handles `epykit.process_chromosomes_dmc` etc. by emitting `DeprecationWarning("epykit.process_chromosomes_dmc is now epykit.dmc.process_chromosomes_dmc")` and returning the function. Shim lives for one minor version (1.0 → 1.1), removed in 1.2.
- Update `README.md` and any cookbook docs that currently show the top-level direct-call pattern to use either `tl.dmc(...)` or the `epykit.dmc.process_chromosomes_dmc(...)` import.

`DMCStore` stays top-level (per decision §1.3).

#### 2.4.3 Rename `pp.unite()` → `pp.set_unite_type()`

Currently at [src/epykit/pp.py:143-159](src/epykit/pp.py:143), `unite()` looks like a verb that performs a union — but it only records `md.uns["unite"]` and does not materialize anything. The lazy-state semantics surprise users.

Change at 1.0:
- Add `pp.set_unite_type(md, type="intersect" | "union")` with the current behavior.
- Convert `pp.unite()` to a thin wrapper that emits `DeprecationWarning("pp.unite() is a state-marker; use pp.set_unite_type() for the same semantics with an honest name")` and calls through.
- Schedule `pp.unite()` removal in 2.0 (one major-version cycle).
- Update README, CLAUDE.md, and any reference docs to use `set_unite_type()` in examples.

### 2.5 Release mechanics

- Merge `p0-fixes` → `main` (51+ commits — this is *the* deferred hygiene item).
- Bump version `0.7.6` → `1.0.0` in `pyproject.toml`.
- Change classifier `Development Status :: 4 - Beta` → `Development Status :: 5 - Production/Stable`.
- Add a `## [1.0.0]` section to `CHANGELOG.md` summarizing the journey from 0.7.2 (P0 fixes + engine freeze + benchmark + paper).
- Tag `v1.0.0` on `main`.

### 2.6 Explicitly out of scope for 1.0

- CLI flags for the `lr+` stack (CLAUDE.md flags these as pending; defer to 1.1).
- Windows extras parity for `pyBigWig` / `pysam`-based features (Linux/macOS-gated stays).
- Any GPU-backend work in `_glm_gpu.py`.
- A v2 API redesign of `apply_multiple_testing_correction` (the polymorphic `DMCStore | DataFrame` overload stays).
- New engines, new DMR callers, new annotation features.

### 2.7 Deferred to 1.1 (the UX-polish release)

These are additive (non-breaking) UX improvements identified during the API brainstorm. They could ship at 1.0 but are not required for a stable API contract — locking them out of 1.0 keeps scope tight; they reach users in 1.1.

- `Literal[...]` type annotations on string-enum kwargs (`test`, `method`, `dispersion`, `fdr_method`, `value` in I/O, etc.).
- `copy=True` kwarg pattern on `pp.*` functions so users can do `md2 = ep.pp.filter_coverage(md, copy=True)` without mutating `md`.
- `ep.set_verbosity("info" | "debug" | "warning")` helper instead of requiring `logging.getLogger("epykit").setLevel(...)`.
- `md.varm["dmc"]` stable alias (in addition to `md.varm["dmc_<resolved>"]`) so consumer code does not need to know which engine ran.
- CLI flags for the `lr+` stack so batch users can reproduce the recommended setup without writing Python.
- Splitting `apply_multiple_testing_correction(DMCStore | DataFrame)` into two purpose-built functions with a deprecation shim on the polymorphic name.

### 3.4 fisher@gse263850 null cell

If you run it, the multi-seed intrinsic-truth column becomes the strongest reviewer rebuttal in the paper. **Recommendation: run it, but as the very last paper-track step** — it doesn't block the rest of the paper writing. If wallclock or compute becomes an issue, ship the paper with the existing 1-seed parallel column and run the 20-seed sweep as a post-acceptance amendment.

## 6. Risks and open questions

- **Q1: Public-surface audit (§2.2) may surface bigger questions.** If the audit finds that, e.g., `clocks.age_clock` has a half-finished API or `entropy_score` returns something users would find surprising, the cleanup may need to escalate beyond doc fixes. Mitigation: time-box the audit at 4 hours; anything that needs more than a kwarg rename or a docstring fix gets deferred to 1.1 and noted in CHANGELOG as "experimental, API may change."
- **Q2: The 20-seed simulator sweep may produce numbers that contradict the existing 1-seed parallel column.** If it does, the paper has to either swap the headline numbers or document the divergence. Mitigation: run it early in the paper track so there's time to react.
- **Q3: Removing the `method="hmm"` deprecation shim is a breaking change.** Any user who has not migrated to `method="segment"` will see an `ArgumentError` after upgrading. Mitigation: it's been deprecated since the `dmr_hmm` → `dmr_segment` rename (commit `846691b`); 1.0 is the natural cutover point; document loudly in the CHANGELOG.
- **Q4: `MethylData._analysis_root` → `analysis_root` rename.** If anyone is reading the private attribute, the rename is breaking. Mitigation: it was underscore-prefixed (private contract), so any user reading it accepted no stability guarantee. Add an `_analysis_root` property alias that warns and returns `analysis_root` if you want to be polite.
- **Q5: `power_stack="auto"` behavior change is the most user-visible break in 1.0.** Anyone today running `power_stack="auto"` on a dataset with `min_n > 2` gets the bare engine (the n≤2 carve-out doesn't engage). After 1.0 they get the full stack and their qvalues will change. Mitigation: prominent CHANGELOG entry under `## [1.0.0] Breaking`; the auto-flip INFO logs make it obvious to anyone watching the log what changed; existing scripts that hard-code `neighbour_combine`/`fdr_method`/`sep_fallback` directly (rather than `power_stack="auto"`) are unaffected.
- **Q6: Demoting five functions from `__all__` will fail import-checkers but not user runtime.** Users importing `from epykit import process_chromosomes_dmc` keep working via the `__getattr__` shim. Users importing `from epykit import *` get one fewer name. Static-analysis tools that read `__all__` (sphinx, some IDEs) may flag the demoted names as "not part of the public API" — this is actually the desired signal. Mitigation: the deprecation shim covers runtime; docs migration covers the rest.
- **Q7: `pp.unite()` is rarely called in user code (it is a state-marker, easily forgotten).** This is the lowest-impact rename. Mitigation: trivial.

## 7. Definition of done

The 1.0 track is done when:
- `p0-fixes` is merged to `main`
- `pyproject.toml` reports `version = "1.0.0"` and `Production/Stable` classifier
- `v1.0.0` tag exists on `main`
- `CHANGELOG.md` has a populated `## [1.0.0]` section
- `README.md` and `CLAUDE.md` describe `lr+` as a power stack, not as defaults
- The `method="hmm"` shim, `unite()` docstring, `dispersion="eb"` docstring, and string-enum type narrowing are all landed
- **§2.4.1**: `power_stack="auto"`/`"lr+"` engages the full four-knob stack at any n; INFO log lines emit when knobs auto-flip; `Literal` annotation rejects unknown strings
- **§2.4.2**: `process_chromosomes_dmc`, `apply_multiple_testing_correction`, `empirical_fdr_for_dmc`, `fisher_exact_vectorized`, `shrink_meth_diff` removed from top-level `__all__`; `__getattr__` deprecation shim in place; README + cookbook docs updated to `tl.dmc` or submodule imports
- **§2.4.3**: `pp.set_unite_type()` exists; `pp.unite()` is a deprecation wrapper; docs migrated to the new name
- All tests still pass on both CI matrices (Ubuntu + Windows × Py 3.9 + 3.12)

The paper track is done when:
- `claims.yaml` is populated with the headline cells
- `paper.md` has `<!-- claim: -->` markers next to all cited numbers
- `regen_all.py --verify` passes on the paper
- The fisher@gse263850 cell is documented in Limitations §10.5
- Paper draft is in a state the user is happy to send to coauthors / a journal

The hygiene track is done when:
- Working tree is clean (no untracked files, no unstaged modifications) on both branches
- `benchmark/idk_if_needed/` no longer exists under that name
- Phase 4 plan file accurately reflects what shipped vs. what didn't
