# epykit 1.0.0 — Pre-submission peer review

**Reviewer framing:** simulated JOSS / Bioinformatics / Nature Methods software-paper review. Goal: find weaknesses before reviewers do. Date: 2026-06-06. Method: 8 parallel module-cluster audits reading the source directly, with every Critical claim re-verified by hand against the cited lines.

**Confidence tags:** `[VERIFIED]` = re-read and confirmed against source by the lead reviewer. `certain` / `likely` / `uncertain` = the auditing agent's confidence, carried forward.

---

## Mental model & claims-vs-implementation

**What it claims to be:** a Python-native, Parquet-backed WGBS methylation pipeline (Bismark `.cov` / MethylDackel `.bedGraph` → DMC → DMR → annotation → HTML report), scanpy-style `pp`/`tl`/`pl` API plus a mirrored CLI, streaming so whole-genome (~22M CpG) data never lands in RAM as one frame. Four DMC engines (`lr`, `welch_t`, `fisher`, `glm`), four DMR callers, an opt-in `lr+` power stack, plus clinical QC, and a head-to-head benchmark paper against eight published tools.

**Audience:** WGBS/EWAS bioinformaticians who want a Windows-compatible, pip-installable, polars-native alternative to the R stack (methylKit/DSS/bsseq).

**Headline mismatch between claims and implementation:**
- The package is named for and fronted by `read_bismark`, but it ingests standard 1-based Bismark `.cov` as 0-based (**C1**) — every real-Bismark CpG is shifted 1 bp.
- The module map and `__init__` expose a large **research-grade surface** (epigenetic clocks, ASM, entropy, imputation, PMD, HMR) at the top level of a SemVer-"Production/Stable" 1.0, several of which are scientifically unsound or unvalidated as implemented (**C3, C2, plus Major cluster**).
- `tl.dvc` documents and defaults to "bartlett" but runs Brown-Forsythe; the docstring states the opposite of what executes (**M-DVC2**).
- "DSS-compatible" chain-merge omits DSS's smoothing/shrinkage step and invents a non-DSS region p-value (**M-DMR4**).
- The benchmark paper's reproducibility rests on a CLI that computes **different q-values than the Python API** (**M-PKG2**) and a dependency floor that **doesn't install a working stack** (**M-PKG1**), with `uv.lock` gitignored.

**Important scope note on paper integrity:** the most damaging correctness bug (C1, the Bismark 1-bp shift) does **not** touch the benchmark paper's numbers — the real cohort (GSE263850) enters through `read_combined_strand_bed` (genuinely 0-based) and the Piao simulation enters through fabricated 0-based fixtures. C1 bites end users running real `*.bismark.cov.gz`, not the published tables. That distinction matters for the rebuttal but does not reduce the severity for users.

## CRITICAL

### C1 — Standard 1-based Bismark `.cov` is ingested as 0-based; every real-Bismark CpG is shifted +1 bp `[VERIFIED]`
**Location:** `convert.py:389` and `convert.py:407` (`pl.col("start").alias("pos")`, no offset, either format); docstring `convert.py:3-9`; `end` discarded at `convert.py:392-393,423`.
**Evidence it's wrong:** The internal convention is unambiguously 0-based — `annotate.py:423` converts GTF "1-based closed → 0-based half-open" to match `pos`; `export.py:82,262` writes each CpG as `pos…pos+1` "0-based half-open, matching the methylstore." Real Bismark coverage rows are 1-based with `start == end` (e.g. `chr1 10497 10497 100 2 0`). The module's *own* docstring states "a 1-based file has `start == end`" yet the code never reads `end` and applies no `-1`. The docstring further claims nf-core/methylseq emits 0-based `.cov` — nf-core just runs Bismark, which emits 1-based `.cov`.
**Why it matters:** Silent +1 shift on every site for the package's primary entry point. Per-CpG DMC p-values survive (a uniform shift cancels), but: (a) annotation / CpG-island context is off by 1 bp at every feature boundary; (b) cross-format `unite` of a Bismark sample with a MethylDackel sample matches the wrong sites or none; (c) exported BED/bigWig coordinates are 1 bp off in a genome browser. A reviewer feeding genuine `.bismark.cov.gz` and checking IGV catches it immediately. No error or warning fires.
**Fix:** Add a per-format coordinate offset (not just a skip-rows entry): `pos = start - 1` for `format="bismark"`; keep `pos = start` for MethylDackel/combined-strand-BED. Optionally auto-detect via the `start == end` heuristic the docstring already describes (requires reading `end`). Then fix the `convert.py:3-9` docstring and the test fixtures that bake in the 0-based assumption (see C1-tests).
**Confidence:** `[VERIFIED]` certain on the convention and the code; the only thing not run is an IGV diff on a real file.

### C1-tests — The test suite green-lights C1 because every Bismark fixture fabricates non-standard 0-based `.cov`
**Location:** `tests/fixtures/synth.py:182-191` (writes `start=pos, end=pos+1`, comments "epykit's converter treats `start` as 0-based"); `tests/test_methyldackel.py:47-55,126` (writes identical `(start=100,end=101)` rows to both a MethylDackel bedGraph and a "Bismark" `.cov`, then asserts identical `pos`).
**Why it matters:** The only cross-check (`md_store.equals(bi_store)`) can pass only if Bismark `.cov` is *assumed* 0-based — it encodes the bug as the expected contract. There is no absolute-coordinate regression anchoring a known `.cov` row → known `pos` → known annotated feature.
**Fix:** Rewrite fixtures to emit real 1-based Bismark `.cov` (`start == end`); add a regression that a Bismark row and a MethylDackel row for the *same physical cytosine* (Bismark `start = mdk_start + 1`) land on the same `pos`, and an end-to-end coord→annotation pin.
**Confidence:** `[VERIFIED]` certain.

### C2 — Annotation silently returns 100% intergenic / 100% open-sea on a chromosome-name mismatch
**Location:** `annotate.py:1143` (`features_by_chrom.get(chrom, empty)`), `annotate.py:1242` (TSS map), `annotate.py:1371-1382` (island overlap keyed on `Chromosome`); no `chr`-prefix normalization anywhere in the module or its callers (`tl.py:1848`, `cli.py:391`).
**Why it matters:** Sites typically carry UCSC `chr1`; an Ensembl GTF uses `1`. On mismatch, every per-chromosome `.get()` returns an empty frame and every site falls through to `feature_type="intergenic"` / `cpg_context="open_sea"` with no exception and nothing above DEBUG. The user gets a plausible-looking genomic-context pie chart that is 100% intergenic — a wrong figure shipped silently. This is the single most likely way to publish an incorrect annotation panel.
**Fix:** After building the feature/TSS/island maps, intersect site chrom names with feature chrom names; if empty (or below a fraction), raise or `logger.warning` showing both name samples. Optionally offer opt-in `chr`-prefix harmonization.
**Confidence:** certain (agent), corroborated by two independent audits.

### C3 — Horvath epigenetic-clock anti-transform drops the `(1 + adult_age)` factor on the negative branch `[VERIFIED]`
**Location:** `clocks.py:238`: `age = np.where(linear < 0, np.exp(linear) - 1.0, linear * 21.0 + 20.0)`.
**Why it matters:** Horvath's canonical `anti.trafo` is `21*exp(x) - 1` for `x<0` and `21*x + 20` for `x≥0` (adult_age=20). The positive branch is right; the negative branch dropped the `21*`. The linear predictor is negative for any predicted age below 20, so every pediatric / young / under-predicted sample gets a garbage (often negative) age. `linear=-0.5` should give `11.7 yr`; the code returns `-0.39 yr`. Adult cohorts (x>0) are unaffected — which is exactly why casual testing misses it. `tests/test_stats_new.py:230-240` re-derives the *same wrong* math (`np.exp(lin_neg)-1.0`) inside the test and never calls `age_clock`, locking the bug in.
**Fix:** `np.where(linear < 0, 21.0*np.exp(linear) - 1.0, linear*21.0 + 20.0)`; parameterize `adult_age`. Rewrite the test to call the function and assert against a hand-computed Horvath reference.
**Confidence:** `[VERIFIED]` certain.

### C4 — ASM phasing reads the bisulfite-converted base at the SNV; C/T & G/A SNVs confound allele with methylation
**Location:** `asm.py:167-176` (`base = read.query_sequence[qry]; if base==ref → hap1 elif base==alt → hap2 else drop`); `query_sequence` holds converted bases in a Bismark BAM (`bam_io.py:204`).
**Why it matters:** In WGBS an unmethylated genomic C reads as T (G→A on the reverse strand). For C/T (and strand-mirror G/A) SNVs, an unmethylated ref-C is miscalled as the alt allele, so haplotype membership becomes a direct function of methylation state — the test then "discovers" allele-specific methylation that is purely an artifact (**fabricated ASM**). For any other C/G-containing SNV, the unmethylated C reads as T, matches neither allele, and the read is dropped — **methylation-dependent dropout** biasing the 2×2 table. Only A/T SNVs are safe, and there is no SNV-type filtering, strand-aware exclusion, or methylation-aware genotyping anywhere. As implemented, ASM output on WGBS should not be trusted.
**Fix:** Restrict anchors to bisulfite-safe SNV classes (exclude C/T, A/G and strand-context-confounded types), or use a methylation-aware genotyper (Bis-SNP / biscuit). At minimum document the restriction and warn.
**Confidence:** certain (agent) on the mechanism; the converted-base claim is grounded in `bam_io.py`.

### C5 — `qc.power` is anticonservative on three compounding axes; it tells users they need fewer replicates than they do
**Location:** `qc.py:721-793` (formula `779-783`).
**Why it matters:** An advertised clinical/cohort planning tool, wrong in the harmful direction on three independent axes that compound: (1) uses the **normal** quantile/CDF (`norm.isf`/`norm.sf`) while the sample-size solver returns n as low as 2 — at n=2/group the two-sided critical value is t≈4.30, not 1.96; (2) assumes **pure binomial** per-site variance `p(1-p)/coverage` with no overdispersion, while real WGBS φ≈1.5–5 (the project's own CLAUDE.md), so true variance is ≈φ× larger; (3) computes power at per-test α=0.05 for a **single** CpG with no multiple-testing burden, while a genome scan tests 1–20M sites. Each pushes power up; together they can tell a user 3 replicates suffice where 10+ are needed → systematically underpowered studies.
**Fix:** Use non-central t (or t critical values with df=2(n−1)); add an overdispersion parameter φ multiplying the binomial term; expose a multiple-testing-adjusted α (accept `n_tests`/target FDR) and document that 0.05 is single-locus only. Compare against `pwrEWAS`.
**Confidence:** certain (agent) on all three mechanisms; severity rank is a reviewer judgment (advertised feature, unidirectional, large).

## MAJOR

### Statistical engines (dmc.py / _glm.py)
- **M-STAT1 — GLM effect size, CI, and SE don't match the GLM test (won't reconstruct).** `dmc.py:1744-1758`; `_glm.py:945-1000` (`delta_method_meth_diff_ci` is **dead code**, grep-confirmed unused). For `test="glm"`, the p-value is the covariate-adjusted deviance LR, but `meth_diff` and its CI come from the **unadjusted** Welch difference of raw group means — in a confounded design (the reason to use GLM) these can differ in magnitude or sign from the adjusted coefficient. `coef_se` is the binomial SE with no φ scaling while the p-value uses φ. Fix: route the glm CI through `delta_method_meth_diff_ci` and φ-scale `coef_se`. `certain`.
- **M-STAT2 — Reported multi-group `df2` ≠ the df used for the F p-value under the default `eb` dispersion.** `dmc.py:1675-1677` (p uses `df_phi`) vs `dmc.py:1711` (emits `df_resid_safe`); `tl.py:263` defaults `eb`. A reviewer recomputing `scipy.stats.f.sf(f, df1, df2)` from the stored columns gets a different p-value than `pvalue`. Fix: emit the denominator df actually used. `certain`.
- **M-STAT3 — `lr` floors `df_phi` at 50; `glm`/`glm_contrast` do not, so the two engines give different p-values on identical data.** `dmc.py:930,935` vs `_glm.py:739-744,927-941`. With `dispersion="site"` the GLM path references `F(1,4)` (~250× more conservative, per the lr-path's own comment) while `lr` references ≈χ²(1). An engine-comparability problem for a benchmark paper. Fix: share one reference convention. `certain`.
- **M-STAT4 — BH/Storey denominator includes NaN-masked (min-samples / degenerate) sites set to p=1, contradicting the documented "excluded from FDR" contract.** `dmc.py:2651-2663,2716-2725`; contract comment `dmc.py:1765-1769`. Conservative (power loss), worst exactly in the `unite=False` / `min_samples_*` workflows where users rely on masking; also pushes Storey π₀→1. Fix: correct over `np.isfinite(pvals)` only, scatter back, leave masked sites NaN. `certain`. (Verified-adjacent: the genome-wide BH itself **is** correctly global, not per-chromosome — `dmc.py:2699-2735` — so that common worry is clean.)
- **M-STAT5 — `empirical_fdr_for_dmc` implements a min-P (Westfall-Young FWER) statistic but documents and names it pooled-null FDR.** `dmc.py:3026-3036` vs docstring `dmc.py:2874-2880`. At 22M CpGs the per-permutation genome-wide min p ≈1e-7, so essentially every site gets `emp_p≈1` → near-zero power, then BH on top is meaningless. Same pattern in `dmr.empirical_fdr_for_dmr` (`dmr.py:1467-1489`). Fix: implement the documented pooled-null estimator, or rename to a FWER procedure and drop the BH framing. `certain`.

### DMR callers (dmr.py / dmr_segment.py)
- **M-DMR1 — Sliding-window combines q-values, not p-values, into the region statistic. `[VERIFIED]`** `dmr.py:484,491,509`: `p_col = "qvalue" if present else "pvalue"`, and that array is fed to both the significance gate and `_stouffer_combine_signed`. After a normal `tl.dmc` run (which always emits `qvalue`) the region "combined_pvalue" is a Stouffer combination of BH q-values — not U(0,1) under H0, so the emitted region p has no calibrated meaning, then it's BH-corrected again. Chain-merge does this correctly (`dmr.py:847-850` separates the columns); sliding-window does not. Fix: read raw `pvalue` for the combine, keep `qvalue` only for the gate. `[VERIFIED]` certain.
- **M-DMR2 — Signed Stouffer ignores spatial correlation and the docstring states the bias backwards.** `dmr.py:205-213` (claim "conservative") vs `dmr.py:256-262` (math). Adjacent WGBS CpGs are positively correlated; `Z=Σz/√k` then *understates* the SD → region p too small → **anti-conservative**, the opposite of the docstring's "conservative" claim. Load-bearing for a paper that reports DMR counts at a region q-threshold. Same defect in `dmr_segment.py:31-39` and `_merge_adjacent_tiles`. Fix: correct the docstring and apply an effective-test/correlation correction, or defer to the read-pooled tile test. `certain`.
- **M-DMR3 — Stratified permutation FDR slices treatment across whole strata, maximally confounding stratum with group.** `dmr.py:1419-1428`; strata map `tl.py:1163-1173` carries no label info. With two equal strata, the permuted "treatment" group becomes the entire first stratum. Empirical p/q under `empirical_strata` are invalid. Fix: permute labels *within* each stratum preserving per-stratum case/control counts. `certain`.
- **M-DMR4 — "DSS-compatible / DSS-equivalent" chain-merge is a loose approximation.** `dmr.py:677-724`, presets `634-662`. (a) No smoothing/dispersion-shrinkage (DSS smooths before the per-CpG stat); chain-merge consumes raw DMC p-values. (b) The region p-value is an epykit signed-Stouffer construct, not a DSS quantity. (c) The `"default"` preset (`alpha=1e-4, dis_merge=500`) is ~10× looser than DSS (`1e-5`, ~50) yet labeled "DSS-equivalent, recommended"; the cited "DSS default: 100" is wrong. Fix: call it "DSS-*style* chaining," document the missing smoothing and non-DSS region p, correct the cited defaults, rename the preset. `certain` on (a)/(b).
- **M-DMR5 — Region-level FDR is computed on post-filter survivors (selective inference); tile path double-corrects.** sliding `dmr.py:616-623`, chain `957-964`, tile `1272`→`1303-1307`→`1090-1091` (BH twice). q-values are anti-conservative as genome-wide FDR; the tile path re-BHs the handful of merged survivors. Fix: correct over all candidate regions tested, don't re-BH after merge, or document that only the permutation `empirical_qvalue` is a valid region FDR. `certain` on mechanism.
- **M-DMR6 — `dmr_segment` uses unsigned Stouffer and per-chromosome BH.** `dmr_segment.py:31-39,42-63,176`. Unsigned combine lets hypo CpGs *add* to a hyper segment's significance; per-chrom BH doesn't control genome-wide FDR. Fix: sign by `meth_diff`, BH genome-wide. `certain`.
- **M-DMR7 — Cross-caller DMR width conventions diverge; 0-based half-open never documented.** sliding `end=pos+window_bp` (a 10 bp cluster → 500 bp DMR), chain `end=last_sig+1`, tile `end=tile_start+tile_size`, segment uses CpG span. Region widths and gene-overlap annotation are method-dependent and not comparable; schemas don't state the coordinate convention. Fix: standardize to the significant-CpG span (or document each) and state 0-based half-open. `certain`. (Note: the interval *base* math is correct — `runs_of_state` `_hmm.py:291`, chain `dmr.py:886` are BED-correct 0-based half-open.)
- **M-DMR8 — `_MAX_DMR_BP = 10_000` silently discards large sliding-window DMRs.** `dmr.py:132-134,327-329` (`return None`). The largest, strongest blocks (broad hypo domains, ICRs) vanish with no flag; hardcoded, sliding-window-only, and contradicts the package's own HMR/PMD callers that report ≥100 kb. Fix: expose as a parameter, default off/large; log drops. `certain`.
- **M-DMR9 — PMD smoother propagates NaN via `0 * NaN` (latent).** `pmd.py:76-79`. A single zero-coverage CpG within 4σ (40 kb default) makes the whole smoothed window NaN → Viterbi driven by the prior → arbitrary PMD boundaries. Latent today because Bismark `.cov` lists only covered sites, but any union/filled store triggers it. Fix: mask NaN before the weighted sum. `certain` on the propagation.

### Differential variability (dvc.py)
- **M-DVC1 — DVC silently returns zero DVCs for the common 2-vs-2 design.** `dvc.py:152-162`. Brown-Forsythe median-centring makes within-group SS *exactly* 0 at n=2, so `f_stat=NaN` everywhere → `is_dvc` always False, with no error. A user runs `tl.dvc` on a 2/2 cohort and concludes "no differential variability" when the test never ran. Fix: detect `ms_within==0` / min-n<3 and warn ("Brown-Forsythe requires ≥3 replicates/group"). `certain`.
- **M-DVC2 — `test="bartlett"` is the default and documented, but Brown-Forsythe always runs; the `tl.dvc` docstring states the opposite. `[VERIFIED]`** `tl.py:1584,1609-1613` ("Only 'bartlett' is supported … Brown-Forsythe would need per-replicate deviations the accumulators don't keep") vs `dvc.py:211-213` ("'bartlett' accepted as a legacy alias; always run Brown-Forsythe"). A user reads "Bartlett," writes it in their methods, and ran median-centred Levene — and the "vs iEVORA" benchmark comparison (iEVORA is Bartlett-based) is mislabeled. Fix: rename the option to `brown_forsythe` end-to-end, warn on the alias, rewrite the docstring. `[VERIFIED]` certain.
- **M-DVC3 — DVC has no minimum-coverage floor; coverage imbalance between groups manufactures false DVCs.** `dvc.py:196,203,256-268`. Variance is computed on raw β; at 1× every β∈{0,1} with huge coverage-dependent binomial variance, so deeper-sequenced case vs control reads as differential biological variance. Every `qc.py` function takes `min_coverage`; DVC takes none. Fix: add a `min_coverage` floor and/or model β-variance as biological + binomial. `certain` on missing floor.

### Clinical QC (qc.py)
- **M-QC1 — `sex_check` forces a 2-class split; correctness depends on an optional dep and degrades silently.** `qc.py:436-466`. Largest-gap clustering *always* splits into two, so a single-sex cohort is mis-split; the only guard (Hartigan dip test) is `except ImportError: pass` — without `diptest` installed, single-sex cohorts are guaranteed mis-split with no warning. Mean chrX β is also a weak discriminator vs the standard chrX/chrY depth ratio. Fix: require minimum gap + proximity to expected centroids, warn when `diptest` is absent, prefer coverage ratio. `certain` on the forced-split/silent-degradation.
- **M-QC2 — `contamination_estimate` is an unvalidated heuristic confounded by biology, presented as a contamination "score."** `qc.py:563-620`. The score is just "fraction of CpGs with 0.2<β<0.8" — driven by cell-type heterogeneity, ASM, imprinting, CNV, none of which is contamination. Not calibrated against spike-in mixtures. Fix: rename to `intermediate_beta_fraction` or replace with a SNP-VAF-bimodality estimator and validate; at minimum document the confounder prominently. `certain` that it's confounded/unvalidated.
- **M-QC3 — `sample_correlation` uses an all-sample listwise intersection that collapses on sparse WGBS.** `qc.py:664-699`. A CpG enters the basis only if *every* sample covers it at ≥`min_coverage`; for N sparse samples the intersection shrinks geometrically and one bad sample drags all pairwise correlations — defeating swap detection. `n_sites_used` is never reported. Fix: pairwise-complete correlations, report per-pair site counts, warn below a floor. `certain` on the listwise behavior.

### Secondary scientific modules
- **M-SEC1 — `clocks.py` `impute_missing=False` silently zero-fills partially-covered CpGs.** `clocks.py:220-233`. "Don't impute" actually means "treat missing β as 0 (fully unmethylated)," biasing ages; a coefficient is dropped only when a CpG is missing in *every* sample. Fix: exclude per-sample-missing CpGs from that sample's dot product, don't substitute 0. `certain`.
- **M-SEC2 — `clocks.py` imputes to the in-cohort mean, not the clock's gold-standard reference, making ages cohort-dependent / non-reproducible.** `clocks.py:216-219`. Re-running one sample alone vs in a batch yields a different age. Fix: accept a per-CpG gold-standard mean; fall back to cohort mean only with a loud warning. `certain` it's cohort mean.
- **M-SEC3 — `impute.py` returns imputed values indistinguishable from observed (no mask); docs invite feeding them to variance/regression analyses where it's destructive.** `impute.py:37-129,1-8`. kNN imputation deflates per-site variance and inflates spatial autocorrelation; if those cells reach DVC or any dispersion test the result is biased with no signal. Fix: return a `was_imputed` mask; document that imputed cells must be excluded from variance/DMC/DMR and are only for PCA/UMAP/clustering. `certain` on the missing mask.
- **M-SEC4 — `entropy.py` plug-in Shannon entropy is downward-biased and coverage-dependent; not comparable across windows of differing depth.** `entropy.py:171-184`. With `window_cpgs=4` (16 patterns) and `min_reads=10`, `normalised_entropy` literally can't reach its documented [0,1] ceiling and a 12× window reads as more entropic than the same window at 10×. (Credit: entropy.py is genuinely read-level — it does *not* conflate H(β) with epiallele entropy — and the log base / normalization are correct.) Fix: Miller-Madow (or NSB) bias correction; document matched-coverage requirement. `certain` on direction.

### Annotation
- **M-ANN1 — Intron intervals use `shift(1)` instead of a running max-end, over-extending into upstream exonic territory for multi-transcript genes.** `annotate.py:221-234`. `gene_id` pools all transcripts, so after a nested exon the next "intron" starts inside an earlier exon. The single `feature_type` is protected by precedence, but `all_overlapping_features` (a documented output) gets spurious `"intron"` and the intron coordinates are wrong. Fix: per-gene cumulative-max end (`cummax().shift(1)`), or merge exons before differencing. `certain`.
- **M-ANN2 — Non-deterministic gene assignment among equal-priority overlaps (unstable sort).** `annotate.py:546-555`. pandas `sort_values` defaults to quicksort (unstable); tied overlaps (two genes' promoters covering one site) yield an arbitrary `gene_id` that can change across runs/pandas versions. Fix: stable sort with an explicit tie-break (`kind="mergesort"`, secondary key). `certain` the sort is unstable.
- **M-ANN3 — Nearest-TSS is a pure-Python per-site loop, on by default, at genome scale.** `annotate.py:1240-1258`, reached whenever `multi_annotation=True` (default), run on the DMC table (millions of rows). Contradicts the module's stated vectorized design. Fix: vectorize per chromosome with one `np.searchsorted`. `certain` it's a Python loop; severity scales with table size.
- **M-ANN4 — GTF promoters are gene-level (outermost TSS only); alternative TSSs missed, undercutting the "HOMER-style" claim.** `annotate.py:419,839,932-936` (parser keeps only `gene`/`exon`, never `transcript`). The refGene path is per-transcript, so the two sources disagree. Fix: parse `transcript` rows (or per-transcript TSS), or document the gene-level limitation. `likely`.

### Packaging / reproducibility / API
- **M-PKG1 — Declared `polars>=0.20.0` is false; the code requires polars ≥1.0. `[VERIFIED]`** `qc.py:87`, `pl/_compute.py:192`, `tl.py:1749` call `DataFrame.pivot(on=...)`; `on=` replaced `columns=` in polars 1.0.0. Fix: `polars>=1.0,<2`; audit all floors against tested minimums. `[VERIFIED]` certain.
- **M-PKG2 — CLI `dmc` and `tl.dmc` compute different q-values on identical input. `[VERIFIED]`** `cli.py:219-229` calls `process_chromosomes_dmc` with no `dispersion` → its default `"site"` (`dmc.py:1977`); `tl.dmc` defaults `"eb"` (`tl.py:263`), the value the paper "claims around." ## The 5 things most likely to draw reviewer criticism

1. **The Bismark 1-bp coordinate shift (C1)** in the package's namesake entry point, with a test suite that encodes the bug as the expected contract. A methylation reviewer will feed a real `.bismark.cov.gz`, check IGV, and see every site off by one. Highest-probability desk-reject trigger.
2. **Reproducibility gap between paper, CLI, and API (M-PKG1/2/4 + M-PKG3).** The documented `pip install` floor doesn't yield a working stack; the CLI computes different q-values than the API the paper claims around; `uv.lock` is gitignored; and no CI job runs the accuracy/calibration tier. "Can I reproduce the numbers?" is the #1 JOSS/Bioinformatics question and the honest answer today is "not from the documented path."
3. **Null calibration of the real engines is never tested (M-PKG3 / tests F2).** For a DMC method paper, "are the p-values uniform under H0 and is FPR≈α" is *the* claim, and `test_calibration.py` validates mock engines. A reviewer will ask for the calibration plot generated by the shipped test suite; it doesn't exist there.
4. **Overstated method fidelity & mislabeled statistics:** "DSS-compatible" without DSS smoothing (M-DMR4); `test="bartlett"` that runs Brown-Forsythe (M-DVC2); sliding-window region p-values built from q-values and described as "conservative" while actually anti-conservative (M-DMR1/2); "empirical FDR" that is a min-P FWER statistic (M-STAT5). Each is a one-line claim a methods reviewer can falsify by reading the code.
5. **A research-grade surface (clocks/ASM/entropy/imputation) shipped as stable 1.0 with real scientific bugs (C3/C4, M-SEC1-4).** The Horvath transform is wrong; ASM is confounded by bisulfite conversion; imputation has no mask. Reviewers who try these advertised features will lose trust in the validated core.

## What the package does well

- **Genuine streaming architecture.** The partitioned-Parquet methylstore + `DMCStore` keep peak memory at O(largest chromosome); chromosome sufficient statistics are integer count sums; numba kernels are non-parallel so there's no float-reduction drift. The core scalability claim holds up.
- **The statistical *primitives* are well-anchored.** Fisher vs `scipy` to 1e-12, BH vs `statsmodels` to 1e-12, IRLS vs `statsmodels.GLM(Binomial)` to 5e-3, Brown-Forsythe vs `scipy.levene` to 1e-6, the quasi-binomial LR closed form, signed-Stouffer sign logic, Newcombe difference-of-proportions CI, forward-backward/Viterbi, and BSmooth WLS are all correct on inspection.
- **Genome-wide BH is correctly global**, not per-chromosome (a common trap, verified clean), and permutation empirical FDR uses the correct `(n_perm+1)` Phipson-Smyth denominator with order-independent per-permutation seeding.
- **`import epykit` degrades gracefully** — every optional dependency (jinja2, plotly, umap, pysam, anndata, pyBigWig) is lazily imported; `__version__` is single-sourced; `__all__` and the deprecation `__getattr__` shim are coherent; LICENSE matches the MIT classifier.
- **annotate.py's coordinate math is internally correct** (GTF/refGene/island all reconciled to 0-based half-open, island>shore>shelf>open-sea precedence and signed TSS distance verified) — *given* a 0-based `pos`. The risk is entirely the upstream C1 input, not the annotation joins.
- **entropy.py is genuinely read-level** and does not commit the common H(β)-vs-epiallele-entropy conflation.
- **Honest disclosure in the core docs:** `CLAUDE.md` already positions `lr+` as a research knob (not a recommended default) and discloses the Stouffer independence assumption and the bare-`lr` anti-conservativeness — the right posture; the gaps above are where code/docstrings drifted from that standard.
