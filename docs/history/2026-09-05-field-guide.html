A software engineer's guide to a genomics codebase

epykit, explained from zero

epykit is a Python library and command-line tool that takes raw DNA-methylation measurements from a sequencer, finds the places in the genome where two groups of samples differ, and writes the result out as tables, plots, and a report. This guide explains the biology only as far as the code needs it, then walks the architecture, the data model, the quality gates, and the places that deserve cleanup.

01 / 23Part 1 · The domain

DNA methylation is a per-position on/off mark, measured as a fraction

DNA is a string over the alphabet A, C, G, T. At certain positions, a cytosine (C) that is immediately followed by a guanine (G) can carry a small chemical tag, a methyl group. That C-then-G pair is called a CpG (the "p" is the phosphate link between them). Methylation at CpGs helps decide which genes a cell uses. Cancer, ageing and development all shift it, which is why people measure it.

A tissue sample contains millions of cells. At one CpG position, some cells are methylated and some are not. So the unit of measurement is not a boolean but a fraction: of the DNA fragments observed at that position, what share carried the mark. epykit calls that fraction β (beta). It lives in [0, 1].

Every row of methylation data is therefore a tiny binomial experiment. Two integers are the raw truth. Everything else is derived.

N_meth     = fragments that were methylated at this CpG
N_unmeth   = fragments that were not
coverage   = N_meth + N_unmeth          # how many fragments we saw
beta       = N_meth / coverage          # the methylation level

The human genome has roughly 28 million CpGs. A whole-genome dataset has one row per CpG per sample. With 8 samples that is well over 100 million rows. That number drives most of epykit's architecture.

02 / 23Part 1 · The domain

WGBS turns a chemical mark into a letter change, and upstream tools count the letters

WGBS means whole-genome bisulfite sequencing. Bisulfite is a chemical that converts an unmethylated C into a U, which the sequencer reads as T. A methylated C is protected and still reads as C. After sequencing, an aligner compares each fragment to the reference genome: where the reference says C, a C in the read means "methylated", a T means "unmethylated".

epykit does not do alignment. Two established tools do that and write per-CpG count files: Bismark (writes .cov) and MethylDackel (writes .bedGraph). Those files are epykit's input. Below is a real row from the synthetic Bismark file the test suite generates.

# chrom  start  end   percent   N_meth  N_unmeth
chr1     1332   1332  35.7143   5       9

Two things about that row matter to an engineer. First, the percent column is redundant with the counts, and epykit drops it. Second, Bismark positions are 1-based while MethylDackel and epykit's internal store are 0-based. Until June 2026 the converter ignored this and stored every real Bismark CpG one base off. That was the top finding of the pre-release review, and the fix (auto-detecting start == end) is why the raw-store manifest is at version 2.

Besides the count files, an analysis needs a samplesheet (a CSV saying which file is which sample and which group it belongs to), and, for annotation, a gene catalogue (GTF file) and a list of CpG islands (a BED file of intervals).

03 / 23Part 1 · The domain

The question is always the same: where do two groups differ, and can we trust it?

A study has a treatment group and a control group (tumour vs normal, knockout vs wild type), each with a few biological replicates. Two replicates per group is common. Four is comfortable. That small n is the central statistical difficulty.

A DMC (differentially methylated cytosine) is one CpG whose β differs between the groups. For each CpG the engine reports the effect size meth_diff (mean β treatment minus mean β control), a confidence interval, and a p-value. A positive difference is hyper, negative is hypo.

Testing 22 million positions means 22 million p-values. At p<0.05 you would get a million false hits by chance alone. So the p-values are corrected for multiple testing (Benjamini-Hochberg, "BH") into q-values, which bound the false discovery rate: at q<0.05, about 5% of the sites you call are expected to be wrong.

A DMR (differentially methylated region) is a stretch of neighbouring CpGs that move together. Regions are what biologists actually report, because a single CpG is noisy and a promoter that shifts as a block is meaningful. epykit derives DMRs from the per-CpG results.

Why the statistics are hard

  • Counts, not measurements. A β of 0.67 from 6 fragments is far less certain than 0.67 from 60. Tests must weight by coverage.
  • Overdispersion (φ). Biological replicates vary more than the binomial model predicts. A "quasi-binomial" test estimates that extra variance, φ, and inflates its uncertainty accordingly. Real WGBS has φ around 1.5–5; the simulator used to tune some heuristics has φ around 0.4. That gap is the source of a documented caveat about the lr+ option.
  • Tiny n. With 2 vs 2 replicates the per-site variance estimate is almost meaningless, so engines pool ("shrink") information across a chromosome.
  • Spatial correlation. Neighbouring CpGs are not independent, which breaks the assumptions behind region-level q-values. The code logs an explicit note about this on every DMR call.
  • Covariates. Age, sex, batch can confound a comparison. A generalised linear model (GLM) with a formula like ~ group + batch adjusts for them.
The one sentence to remember

Input is two integers per CpG per sample. Output is a p-value and an effect size per CpG, then merged into regions. Everything in between is about doing that at 22 million positions without loading them all into memory and without lying about uncertainty at n=2.

05 / 23Part 2 · The system

The pipeline is a chain of on-disk stores; each step reads one and writes the next

Ingest

Parse count files with Polars, split by chromosome, write one Parquet file per (sample, chromosome). Fingerprint each input so a rerun is a no-op.

Preprocess (pp)

Drop low and extreme coverage, optionally rescale counts per sample, record the site-alignment policy. Each writes a new store.

Analyse (tl)

Per-CpG test streamed chromosome by chromosome, then correction, region merging, annotation. Results attach to the object, not the store.

06 / 23Part 2 · The system

The methylstore: Hive-partitioned Parquet, one file per sample per chromosome

The store is a directory tree. The two partition keys are in the path, so reading one sample's chromosome 3 is a single file open, and reading "all of chromosome 3" is a glob. The tree below is the real output of the demo run, showing one sample.

methyl_store/
└── .cache/
    ├── raw/
    │   ├── sample=treatment_1/
    │   │   ├── .epykit_raw_manifest.json
    │   │   ├── chrom=chr1/part-0.parquet
    │   │   ├── chrom=chr2/part-0.parquet
    │   │   └── … chr3, chr4, chr5
    │   └── sample=…  (8 samples in the fixture)
    ├── filtered/            ← same shape, after pp.filter_coverage
    └── dmc/
        └── lr/              ← DMC results, one file per chromosome
            ├── .epykit_dmc_manifest.json
            └── chrom=chr1.parquet …

Every partition has the same eight columns. Counts are 32-bit integers on purpose: a 22-million-row chromosome set at Int32 is half the size of Int64, and no count ever overflows it.

The one architectural rule

Never load the whole genome into one frame. Access is pl.scan_parquet on a partition glob, or an explicit loop over chromosomes. Peak memory is O(largest chromosome). The word "streaming" in the code always means this loop.

Two manifest layers

  • Per-sample, per-step (.epykit_raw_manifest.json, _filter_, _normalize_): a fingerprint of the input file plus parameters. Lets convert and filter skip samples already done.
  • Pipeline-level (.epykit_manifest.json at the analysis root): a list of completed stages with input signatures, used only when a caller passes resumable=True. Both live in _cache.py.

State is derived, never stored

There are no is_filtered booleans. md._filtered is a property that scans uns["_store_history"] for a step named filtered. md.state is the ordered list of steps. This is the real log from the demo:

[{'step': 'raw',      'path': '…/.cache/raw',      'n_sites': 80000},
 {'step': 'filtered', 'path': '…/.cache/filtered', 'n_sites': 78412},

When you add a preprocessing step, append to this list. Do not add a flag.

Properties worth knowing

  • md.dmc resolves the most recent DMC table via uns["dmc"]["last_key"], preferring the _annotated variant. If the table was never materialised it reads it back from the on-disk DMCStore.
  • md.dmc_store reopens the streaming handle from uns["dmc"]["store_path"].
  • md.treatment_ids / md.control_ids filter obs.treatment.
  • md.save(path) writes obs.parquet, one Parquet per varm table, Parquet sidecars for DataFrames in uns, and a methyldata.json. A DMCStore-backed table is hard-linked per chromosome instead of re-encoded, because a single 22M-row write needs a second copy in RAM.
Watch for

varm and uns are mutated in place by every function. There is no schema for uns; it is a bag of ~25 keys with different shapes, and save() serialises the non-DataFrame ones with json.dumps(default=str). Anything that is not JSON-native silently becomes a string on reload.

Two front doors, one engine: the scanpy-style API and a mirrored CLI

import epykit as ep

md = ep.read_bismark("samplesheet.csv",
        treatment_group="cd55", control_group="control",
        assembly="hg38", store_dir="methyl_store")

ep.pp.filter_coverage(md, lo_count=10, hi_perc=99.9)
ep.pp.set_unite_type(md, type="intersect")

ep.tl.qc(md)                 # -> md.obs columns, md.uns["qc_*"]
ep.tl.dmc(md, test="auto")   # -> md.varm["dmc_lr"], md.uns["dmc"]
ep.tl.dmr(md)                # -> md.uns["dmr"]
ep.tl.annotate(md, gtf="gencode.v49.gtf",
               cpg_islands="hg38_cpg_islands.bed")

md.save("cd55_analysis")
md.report("cd55_report.html")
ep.pl.volcano(md, save="volcano")

Every function mutates md and returns None. That is the scanpy convention: the object is the session. tl.dmc, tl.dmr and tl.annotate also auto-write a TSV under <store>/results/ unless told not to.

Each subcommand calls the same engine functions the API does (process_chromosomes_dmc, call_dmr_*). Parity is enforced by subprocess tests (test_cli_api_parity.py) because it once drifted: the CLI computed different q-values than the API until a review caught it. The lr+ research knobs are deliberately API-only.

Beyond the core (research-grade, exported at top level)

  • tl.dvc / tl.dvr: differential variability, not mean.
  • tl.pmd, tl.hmr: partially-methylated and hypomethylated domain finders.
  • tl.asm, tl.entropy: read BAM files directly (need pysam, Linux/macOS).
  • ep.age_clock, ep.deconvolve, ep.impute_knn_beta: epigenetic clocks, cell-type deconvolution, imputation.

The peer review flagged several of these as unvalidated and proposed an epykit.experimental namespace. That move has not happened yet.

09 / 23Part 2 · The system

Inside the DMC engine: a chromosome loop, per-site accumulators, and a store that is rewritten in place

What tl.dmc does before and after the engine

resolve
Choose the engine.

test="auto" becomes fisher at n<2 (only with allow_n1=True) or lr otherwise. Any formula or contrast forces the GLM path via _run_dmc_contrast. Removed engine names raise ValueError with a migration hint.

guard
Refuse degenerate designs.

n<2 per group without allow_n1, union-mode with no min_samples_* floor, materialize=False combined with any post-processor that needs the full table.

stack
Apply power_stack.

If "lr+", flip neighbour_combine, fdr_method="fdr_tsbh", sep_fallback on. Off by default.

resume
Optional checkpoint.

With resumable=True, hash store path + samples + every parameter, look it up in the pipeline manifest, and load the sidecar Parquet instead of computing.

run
Engine, correction, post-processors.

process_chromosomes_dmc → apply_multiple_testing_correction → optional neighbour combining (adds pvalue_combined, never overwrites pvalue) → optional permutation FDR.

record
Write uns["dmc"].

A 24-key dict of what ran, including last_key and store_path, then the TSV auto-export and a FutureWarning about a deprecated column.

The canonical result schema (real columns from the demo)

chrom  pos  strand  n_case  n_control
mean_beta_case  mean_beta_control
meth_diff  meth_diff_ci_lo  meth_diff_ci_hi
pvalue  qvalue  reject
log2_odds_ratio_pooled
log2_odds_ratio        # NaN-filled, deprecated

Every engine emits exactly these, so downstream code (DMR, plots, report, export) never branches on which test ran. The GLM adds coef_treatment, coef_se, coef_treatment_log2; multi-group contrasts add f_stat, df1, df2 and per-level means.

Execution backends

  • backend="sequential" (default) walks chromosomes in-process. "dask" and "ray" submit one task per chromosome; both live in _compute.py behind optional extras.
  • glm_backend="gpu" routes the IRLS inner loop through CuPy (_glm_gpu.py). Only the GLM path; lr is closed-form numpy.
  • Hot loops that need it are numba @njit, compiled lazily on first call and cached in a module global (_SMOOTH_BOX_NJIT_FN, _BSMOOTH_NJIT_FN).

Statistics, honestly: four engines, one recommended, one research knob with a known problem

test=ModelUse whenCaveat the code itself states
lr default n≥2Quasi-binomial likelihood-ratio χ² on counts pooled per group, with McCullagh-Nelder dispersion φ estimated from replicates. Closed-form on streaming accumulators.Almost always. The benchmark paper's claims are about this engine.Needs ≥2 replicates. Dispersion at n=2 is shrunk toward the chromosome pool ("eb").
welch_tWelch t-test on per-replicate β values.Quick look; sanity check.Ignores coverage; anti-conservative near β = 0 or 1.
fisher n=1 fallbackFisher exact test on counts pooled across replicates.One sample per group, nothing else works.Ignores between-replicate variance. Warns once per process when chosen explicitly.

Four names were removed in 0.7.5 and now raise with a hint: logit_t → welch_t, bb_lr and score → lr, cmh → a formula with a batch term. The header docstring of dmc.py still lists score and logit_t as live engines; it was not updated.

The GLM path in one line

formula "~ group + age"  ──patsy──▶  design X (n_samples × p)
  ──irls_binomial_batch──▶  β̂, SE, deviance for every site at once
  ──resolve_contrast + wald_test──▶  pvalue, f_stat/df, CI on meth scale
power_stack="lr+" is not a free upgrade

It bundles four extensions: Stouffer-combining p-values across CpGs within 500 bp, two-stage BH, a Fisher fallback under quasi-complete separation, and empirical-Bayes dispersion shrinkage. They were tuned on a simulator with φ≈0.4. On the real cohort GSE263850 at q=0.05, lr+ calls about 13× more DMCs than bare lr, which the authors read as false-positive drift, not sensitivity. It is off by default, documented as exploratory, and the CLI deliberately does not expose it.

Do not change its defaults without re-running the ablations in benchmark/. The CI job benchmark-regen hashes engine output on a small slice and fails on drift.

Dispersion strategies (dispersion=)

  • site: per-site Pearson estimate. Noisy at small n.
  • chrom: one pooled φ per chromosome for every site.
  • shrink: fixed-weight average of the two.
  • eb (default in tl.dmc): method-of-moments inverse-gamma prior; weight depends on the site's degrees of freedom.

Note the default is "eb" in tl.dmc but "site" in the lower-level process_chromosomes_dmc and in tl.dmr. That asymmetry is real and bit the CLI once.

Calibration is tested

The slow tier runs each engine on null data (shuffled labels) and checks the false-positive rate at α=0.05 with a Kolmogorov-Smirnov test on the p-value distribution. Recorded results: lr 0.047, welch_t 0.038, glm 0.038. That test is the guardrail for any refactor of dmc.py.

12 / 23Part 2 · The system

The periphery: annotation, QC, plots, report and export sit around the same object

Annotation · annotate.py (1,500 lines)

Streams a GTF or UCSC refGene.txt into pandas frames of genes and exons, builds promoter / UTR / exon / intron / TTS / non-coding intervals, then overlaps sites per chromosome with bioframe. Ties resolve by a HOMER-style priority table. CpG islands come from a BED; shore = ±2 kb, shelf = ±4 kb, else open sea.

  • Three module-level LRU caches (parsed GTF, built feature index, parsed UTRs) sized by env vars.
  • Raises when site and catalogue chromosome names share zero overlap (chr1 vs 1), warns under 50%. Before June it silently produced a 100%-intergenic pie chart.
  • Applies to the DMC table and, since the last commit, the DMR table with the same columns.

QC · qc.py (877 lines)

tl.qc writes per-sample metrics onto obs: bisulfite conversion rate (from non-CpG contexts; reported, never applied), global methylation, coverage uniformity. Opt-in: sex check from chrX β, a bimodality score labelled "contamination", all-vs-all sample correlation for swap detection, and a power calculator rebuilt in June on a non-central t with overdispersion.

Plots · pl/ (14 modules)

Volcano, MA, Manhattan, PCA, UMAP, heatmaps, karyogram, TSS and gene-body metaplots, DMR box/violin/heatmap, annotatr-style bars, a figure_grid composer. All matplotlib, themed by _style.py with named palettes (default, publication, colorblind).

The good decision: pl/_compute.py holds every data-preparation function (one lazy scan per plot, results cached in uns["_report_cache"]), and both the matplotlib plotters and the Plotly twins in pl/_plotly.py consume it. One source of truth for "what does this plot show".

Report · report.py + templates/

A single-file HTML dashboard: Jinja2 template, Plotly figures (inlined bundle by default, ~4 MB), a sidebar with per-section status, sortable tables, an auto-generated Methods section with citations, and the provenance dict. Every section degrades to "not run yet" if its input is absent. Jinja2 and Plotly are lazy imports behind the report extra.

Export and interop

  • export.py: TSV/CSV tables, per-sample bedGraph and bigWig (streamed per chromosome), DMC and DMR BED.
  • anndata_io.py: AnnData / MuData for the single-cell ecosystem.
  • methylkit_io.py, multiqc_export.py, nfcore_qc.py: bridges to the R package methylKit, to MultiQC, and to nf-core/methylseq output.
  • bam_io.py: reads aligned BAM for ASM and entropy; pysam, no Windows.

Random access · query.py

query_region(store, chrom, start, end), query_regions, query_sites. Builds the partition path directly and pushes the position filter into the Parquet reader so row groups outside the window are never read. This is what makes the store usable without a tabix index.

13 / 23Part 2 · The system

Conventions that are load-bearing: break these and something downstream breaks quietly

Library code never prints

Every module uses logger = logging.getLogger(__name__). Only cli.py calls print, and only for the final result line. A test (test_no_print_outside_cli.py) greps for violations. Reason: notebooks and host applications import epykit and must own stdout.

Temporary files go where set_tmp_dir says

ep.set_tmp_dir(path) sets tempfile.tempdir and mirrors it into TMPDIR, TEMP, TMP so Dask and Ray workers inherit it. Windows %TEMP% on C: is routinely too small for a genome. Never hardcode a temp path.

Windows is a first-class CI target

Matrix is {ubuntu, windows} × {3.9, 3.12}. pysam and pyBigWig have no Windows wheels, so bam, methylkit and export extras are gated in pyproject.toml and the modules raise a helpful ImportError. Tests skip via importorskip. Path handling is pathlib throughout; hard-links fall back to copies.

Optional dependencies are imported inside functions

Plotly, Jinja2, anndata, umap, joblib, cupy, dask: all lazy. That is the legitimate reason for many of the 179 in-function imports. The illegitimate ones import warnings, pathlib and logging inside functions that already have them at module scope.

Deprecation policy is real and scheduled

  • Removal in 1.1: the NaN-filled log2_odds_ratio column, pp.unite, the dmr_hmm shim, csv* keyword aliases.
  • Removal in 1.2: the module-level __getattr__ in __init__.py that forwards five demoted engine functions to epykit.dmc.
  • Removal in 2.0: MethylData._analysis_root.

Tests assert on these warnings, so pyproject.toml lets epykit's own DeprecationWarning and UserWarning through the filter. Do not silence them globally.

One-shot warnings use process-global flags

_FISHER_WARNED and _DMR_FDR_NOTED in tl.py. They fire once per interpreter, which means the second test in a session never sees them. Known, documented, not yet fixed.

Version pins carry reasons

polars>=1.0,<2 because DataFrame.pivot(on=) changed at 1.0; numba>=0.60 for numpy 2; numpy<3. The comments in pyproject.toml say why. uv.lock is committed for reproducible CI; the benchmark protocol pins thread counts to 1 for determinism.

Coordinates

The store is 0-based. GTF is 1-based closed and gets converted on parse. BED is 0-based half-open and passes through. Bismark input is 1-based and is shifted on ingest since manifest version 2. If a number is off by one, it is this.

How the tests are built

tests/fixtures/synth.py generates a synthetic dataset with known truth: 8 samples, 5 chromosomes, 2,000 CpGs each, 500 planted DMCs, 10 planted DMRs, β around 0.30, coverage around 20. It writes real 1-based Bismark files and a truth Parquet. conftest.py builds it once per session and hands each test a fresh MethylData on its own store directory.

Helpers compute power, empirical FDR, effect-size bias and DMR recovery against the truth table. Tests assert on statistics, not on snapshots. The fast tier stays under a minute or two; anything slower carries @pytest.mark.slow and --strict-markers rejects unregistered marks.

Coverage of concerns

  • Engine oracles against statsmodels / scipy (test_engine_oracles.py).
  • Null calibration under overdispersion for lr, welch_t, glm.
  • CLI/API parity via subprocess.
  • Coordinate conventions end to end (Bismark row → pos → annotated feature).
  • Streaming contract: materialize=False paths, DMCStore round trip.
  • A grep test that no library module calls print.
  • GPU parity tests skip cleanly without CuPy.
What the gates do not check

ruff runs pyflakes only. mypy runs with no_strict_optional, follow_imports = silent, ignore_missing_imports, and does not check the bodies of untyped functions. "Passes lint and types" currently means "no undefined names and no unused imports". The pre-commit config includes ruff-format, but the code is not formatted to it, so the first run would touch every file.

Correctness debt: known, documented, and not to be touched without the accuracy suite in hand

These come from the June review and its remediation summary. They were deferred on purpose: each changes numbers, so each needs a benchmark re-run or a statistician's decision, not a refactor.

C4
ASM reads bisulfite-converted bases at SNVs

In asm.py, haplotype assignment uses the converted read base, so C/T and G/A variants confound allele with methylation. Output can be fabricated. Fix is well specified (restrict to bisulfite-safe SNV classes) but pysam-gated, so it needs a Linux box. Highest-severity open item.

M-STAT4
BH includes NaN-masked sites as p=1

Conservative direction, but it touches the genome-wide correction; validate against the accuracy suite.

M-STAT2
Multi-group df reporting

wald_test uses an adaptive F / χ² reference, so the stored df2 does not let a reader reproduce the p-value. A first attempt was test-falsified and reverted.

M-DMR3/5/6
Region-level FDR details

Stratified permutation shuffles across strata instead of within; region FDR is computed on post-filter survivors (selective inference) and the tile path applies BH twice; dmr_segment uses unsigned Stouffer with per-chromosome BH.

M-STAT1/3
GLM effect-size CI and the φ floor

The GLM path has an unused delta_method_meth_diff_ci; the DF_PHI_FLOOR is applied inconsistently between lr and glm.

minor
Smaller items with a clear fix

Standardise DMR start/end width across callers (M-DMR7); make _MAX_DMR_BP a parameter (M-DMR8); vectorise nearest-TSS lookup (M-ANN3); pairwise-complete sample_correlation (M-QC3); region_beta uses a closed interval and reads only part-0.

Rule of thumb

If a change can alter a p-value, it is not cleanup. Land it separately, with a benchmark note, and let the benchmark-regen hash fail on purpose so the diff is visible.

The mental model, one last time

Two integers per CpG per sample, partitioned on disk by sample and chromosome. A loop over chromosomes turns them into one p-value and one effect size per site, written straight back to disk. Regions, annotation, plots and the report read from there. The object in your hand is a path plus two dictionaries. Keep it that simple.
